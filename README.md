# Component-Level Aging Prediction for DNN Accelerators

**Accurate surrogates, saturated objectives, and when aging-aware mapping pays off**

Mrinal Sharma, Satyam Singh — Department of ECE / AI–ML

This repository contains the code, released checkpoints, measurement scripts and paper for a
simulation study of transistor aging in DNN accelerators. We model a 28-node accelerator as a
graph, train a Hybrid GNN–Transformer to predict per-component aging and a 10-step aging
trajectory, and then test whether that prediction helps two decisions: offline layer-to-cluster
mapping (NSGA-II) and runtime remapping (PPO).

- Paper: [`paper/main.pdf`](paper/main.pdf) (source: [`paper/main.tex`](paper/main.tex))
- Remaining training experiments: [`TRAINING_PLAN.md`](TRAINING_PLAN.md)

All data are simulated. Every number in the paper is regenerated by a script from the
checked-in checkpoints, the simulator and the physics aging model.

## Problem

Inference accelerators run the same workloads for months. The same MAC clusters execute the same
layers, and the same SRAM banks hold the same weights, so stress concentrates in the same places.
Three degradation mechanisms follow from that stress:

- **NBTI** (negative bias temperature instability) shifts threshold voltages.
- **HCI** (hot carrier injection) degrades drive current.
- **TDDB** (time-dependent dielectric breakdown) eventually destroys the gate oxide.

A runtime scheduler that decides which cluster runs which layer needs aging estimates at the
level of architectural components, and ideally a forecast. This project builds such a predictor
and measures whether it actually improves mapping and control decisions.

## Key findings

1. **The predictor is accurate.** On 150 held-out graphs it reaches R² = 0.996 (95% CI
   0.9956–0.9966, MAE 0.0052 against 0.107 for a mean predictor). The 10-step trajectory head
   reaches R² = 0.945 (MAE 0.036 against 0.104 for persistence). One graph takes about 5 ms on
   an RTX 3050 laptop GPU.
2. **Accuracy does not translate into better mappings here.** Used as an NSGA-II surrogate, the
   predictor reports 15–28% lower peak aging than single-cluster placement. Scored by the
   physics model, every load-spreading mapping achieves the same 21.6–21.7%. That includes
   round-robin, same-budget random search, surrogate NSGA-II and NSGA-II on the physics model.
   Once load is spread, peak aging sits on a NoC router whose stress the mapping cannot change.
   The surrogate's extra predicted gains are model error that the optimizer exploits.
3. **Process variation is what makes aging-aware mapping worthwhile.** With per-node lognormal
   variation in the physics model, NSGA-II beats round-robin by 8.1 ± 5.9% (σ = 0.1) and
   15.3 ± 11.0% (σ = 0.2), up to 25% on some simulated dies.
4. **The runtime environment leaves no headroom.** A greedy one-step oracle (1.572) scores the
   same as always rotating (1.574). The 960-step PPO run (mean 1.032) does not beat rotation.
5. **A configuration mismatch was found and fixed.** The training data were simulated on a 4×4
   PE array while the released optimizer ran on 16×16, which fed the predictor
   out-of-distribution inputs. The PE array is now one shared setting.

## How the pipeline works

```text
DNN workload layers (ResNet-50, BERT-Base, MobileNetV2, EfficientNet-B4, ViT-B/16)
      |
      v
Roofline-style analytical simulator  (simulator/timeloop_runner.py)
      |   per-component switching activity, utilization, traffic, latency, energy
      v
Feature builder -> 8 features per node  (features/feature_builder.py)
      |
      v
Accelerator graph: 16 MAC clusters, 8 SRAM banks, 4 NoC routers, 92 directed edges
      |   (graph/accelerator_graph.py)
      v
Hybrid GNN-Transformer  (models/hybrid_gnn_transformer.py)
  input projection -> 3x GCN -> GAT -> 2-layer transformer -> MLP head
      |                                  |
      v                                  v
Per-node aging score in [0,1]     10-step trajectory head (models/trajectory_predictor.py)
      |                                  |
      +----------------+-----------------+
                       |
          +------------+-------------+
          v                          v
NSGA-II mapper                  PPO runtime controller
(optimization/nsga2_optimizer)  (rl/environment.py, rl/trainer.py)
peak aging, latency, energy     hold / move / rotate / rebalance actions
```

Training labels come from textbook NBTI, HCI and TDDB models
(`aging_models/aging_label_generator.py`), combined as
`0.40·NBTI + 0.35·HCI + 0.25·TDDB`. The coefficients are uncalibrated.

## Installation

Python 3.11 is recommended; the scripts were tested with 3.11 on Windows 11. PyTorch did not
install under Python 3.14 at the time of writing.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

For CUDA, install the PyTorch build that matches your driver from pytorch.org before
`torch-geometric`. A conda environment is also provided:

```bash
conda env create -f environment.yaml
```

A 4 GB GPU such as the RTX 3050 Laptop is enough. Use `--gpu-4gb`, or let `run_eval.py` detect
low VRAM. Everything also runs on CPU, more slowly.

## Reproducing the paper (no training)

These commands use only the released checkpoints, the simulator and the physics model. Run
them on an otherwise idle machine, because `extended_analysis.py` measures latency.

```bash
# 1. Released checkpoints reproduce every metric in eval_results.json (~5 min).
python scripts/verify_results.py                 # prints "ALL METRICS REPRODUCED"

# 2. Trajectory figures, NSGA-II table, Pareto/heatmap, PPO vs fixed policies (~20 min).
python scripts/measure_paper_figures.py

# 3. Bootstrap CIs, latency, physics-scored mapping study, runtime oracle (~35 min).
python scripts/extended_analysis.py
#    re-time latency only:  python scripts/extended_analysis.py --latency-only

# 4. Process-variation scoping study (~5 min).
python scripts/variation_scoping.py
python scripts/variation_scoping.py --pe-array 16,16

# 5. Remaining figures and LaTeX tables.
python generate_figures.py
```

The first run of step 1 regenerates the dataset in `data/processed/` if it is missing; this is
simulation only. The released dataset regenerates bit-exactly from code.

## Training

The release was produced with:

```bash
python run_eval.py --quality --device cuda --gpu-4gb --dataset-size 1500 \
  --pred-epochs 60 --pred-patience 16 --traj-epochs 75 --traj-patience 18 \
  --nsga-pop 20 --nsga-gen 20 --ppo-iters 30 --ppo-steps 32
```

Quick checks:

```bash
python run_eval.py --smoke                        # small end-to-end run
python run_eval.py --smoke --device cuda --gpu-4gb
```

Measured cost on an RTX 3050 laptop:

- **Training:** about 1.5 s per epoch per model at 1,500 samples, so a `--predict-only` run
  takes about 4 minutes.
- **PPO:** about 1.5 s per 100 environment steps.

Before running new experiments, pass a separate `--ckpt-dir` and `--results-path` so the
released `checkpoints/` and `eval_results.json` stay untouched.

**What to train next** is listed in [`TRAINING_PLAN.md`](TRAINING_PLAN.md), in priority order:

| | Run | Closes |
|---|---|---|
| E0 | Retrain on the 16×16 PE array | the PE-array choice |
| E1 | 5 training seeds | single seed |
| E2 | Architecture ablation, including MLP-only (`--components none`) | no ablation |
| E3 | Data scaling (500 to 15,000 samples) | small dataset |
| E4 | Variation-aware surrogate, scored by the physics model | the main open question |
| E5 | PPO in the variation setting with a 20× budget, 3 seeds | PPO negative result |
| E6 | Optional model and simulator upgrades | simplified inputs and labels |

## Command-line reference

`run_eval.py` options:

| Option | Default | Meaning |
|---|---|---|
| `--smoke` / `--quality` / `--full` | smoke | Preset sizes (200 / 1,000 / 40,000 samples, with matching epochs and budgets). |
| `--dataset-size N` | preset | Number of synthetic snapshots. |
| `--pred-epochs`, `--pred-patience` | preset | Predictor training length and early stopping. |
| `--traj-epochs`, `--traj-patience` | preset | Trajectory head training length and early stopping. |
| `--nsga-pop`, `--nsga-gen` | preset | NSGA-II population and generations. |
| `--ppo-iters`, `--ppo-steps` | preset | PPO iterations and steps per iteration. |
| `--seed N` | 42 | Model initialisation, training and PPO seed. |
| `--data-seed N` | 42 | Synthetic dataset draw. |
| `--components LIST` | all | Ablation: any of `gcn,gat,transformer`, or `none` (MLP only). |
| `--predict-only` | off | Stop after the predictor and trajectory stages. |
| `--ppo-only` / `--nsga-ppo-only` | off | Skip earlier stages and load the predictor from `--ckpt-dir`. |
| `--ppo-use-predictor` | off | PPO environment uses the learned predictor and trajectory head. |
| `--ppo-hidden N` | 128 | PPO actor-critic width. |
| `--pe-array R,C` | 4,4 | Simulated PE array, shared by data generation and runtime. |
| `--aging-technology NAME` | custom | `28nm_bulk`, `14nm_finfet`, `7nm_finfet` presets. |
| `--aging-variation S` | 0 | Per-node lognormal process variation σ. |
| `--aging-recovery C` | 0 | NBTI recovery coefficient. |
| `--dataset-source imported_trace` | synthetic | Use `--workload-traces` / `--activity-traces` files instead of the simulator. |
| `--device cpu\|cuda`, `--gpu-4gb`, `--ultra-low-vram` | auto | Device and memory profile. |
| `--ckpt-dir DIR`, `--results-path FILE` | `checkpoints/`, `eval_results.json` | Output locations. |
| `--resume` / `--fresh` | fresh | Resume an interrupted run stage by stage (for SLURM requeue). |

Each non-default value of `--dataset-size`, `--data-seed`, `--pe-array`, `--aging-variation`,
`--aging-recovery` and `--aging-technology` gets its own dataset cache file in
`data/processed/`.

## Limitations

- **Synthetic, uncalibrated data.** The aging models are textbook forms with uncalibrated
  coefficients, and there is no silicon validation.
- **Single training seed.** The bootstrap CIs cover test sampling only.
- **Saturated mapping objective.** Simulated router traffic does not depend on the mapping, and
  without variation all MAC clusters are identical.
- **Simplified labels.** TDDB is effectively zero, and trajectory labels are a smooth
  extrapolation of the current state.
- **Simplified model inputs.** The graph layers ignore edge attributes, and feature 3 duplicates
  feature 0.
- **Reduced workloads.** Workloads are 12–15-layer abstractions without attention score or
  softmax operations.
- **No architecture ablation yet.**

[`TRAINING_PLAN.md`](TRAINING_PLAN.md) maps each item to the run that addresses it.

## Corrections to earlier results

Earlier versions of this repository reported numbers that do not hold:

- a 49–70% peak-aging reduction;
- PPO beating its baselines;
- a 40,000-sample dataset;
- an ablation table;
- several supplemental figures.

Those figures were produced by a plotting script that generated curves rather than measuring
them, and the ablation values were entered by hand. They have been removed. Specific fixes:

- **NSGA-II block of `eval_results.json`.** It is not comparable to the paper, for three
  reasons, all fixed in `run_eval.py`:
  - the trajectory head fine-tuned the shared predictor encoder before NSGA-II used it;
  - the reported reduction compared the penalised objective `f1` with an unpenalised peak;
  - NSGA-II simulated a 16×16 PE array while the dataset was generated on 4×4.
- **PPO baselines.** `ppo.baselines` in `eval_results.json` are per-step means, while PPO
  rewards are per-episode sums. The paper compares both on the same per-episode scale.
- **References.** Six references had wrong metadata or did not exist as cited; all are
  corrected.

## Troubleshooting

- **`WinError 6714` on import (Windows).** Import `torch_geometric` before `matplotlib`. The
  scripts in this repo already do.
- **`UnicodeEncodeError` when redirecting output on Windows.** This is fixed in `run_eval.py`,
  which forces UTF-8 output.
- **CUDA out of memory.** Use `--gpu-4gb` or `--ultra-low-vram`. `run_eval.py` also retries
  automatically with `--ultra-low-vram`.
- **Unexpected metrics after changing settings.** Check `data/processed/` for a matching cache
  file. Every setting that changes the samples is now part of the file name.
